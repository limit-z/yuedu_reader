## 5. 为什么没有直接使用 `mc`

本机原本的 `mc` 命令并不是 `MinIO Client`，而是：

- `GNU Midnight Commander`

所以如果直接执行依赖 `mc` 的脚本，会弹出蓝色双栏文件管理界面，而不是执行 MinIO 删除命令。

检查方式：

```bash
type mc
mc --version
```

本次检查结果：

```bash
mc is /opt/homebrew/bin/mc
GNU Midnight Commander 4.8.33
```

因此，本次没有继续依赖本机 `mc`，而是改用 `Python + boto3` 直连 MinIO 执行清理。

## 6. 推荐重置方式

### 6.1 方式一：优先推荐，直接执行一键脚本

项目内已经准备了一键重置脚本：

- [reader-reset-remote-test-data.sh](/Users/yabin/code/ruoyi/RuoYi-Vue-Plus/script/bin/reader-reset-remote-test-data.sh:1)

如果本机已经安装正确的 `MinIO Client`，可以直接执行：

```bash
READER_DB_HOST="${READER_DB_HOST}" \
READER_DB_PORT="${READER_DB_PORT}" \
READER_DB_NAME=reader \
READER_DB_USER="${READER_DB_USER}" \
READER_DB_PASSWORD="${READER_DB_PASSWORD}" \
bash /Users/yabin/code/ruoyi/RuoYi-Vue-Plus/script/bin/reader-reset-remote-test-data.sh --all-bucket
```

说明：

- `--all-bucket` 表示：
  - 清空 MinIO 的 `ruoyi` bucket
  - 删除全部 `service = 'minio'` 的 `sys_oss` 记录
  - 清空所有阅读器业务表 `reader_*`

### 6.2 方式二：当本机 `mc` 冲突时，使用 Python 直接清理

如果本机 `mc` 被 `Midnight Commander` 占用，可直接用下面这段 Python 脚本清理：

```bash
python3 - <<'PY'
import os
import pymysql
import boto3
from botocore.client import Config

DB = dict(
    host=os.environ['READER_DB_HOST'],
    port=int(os.environ['READER_DB_PORT']),
    user=os.environ['READER_DB_USER'],
    password=os.environ['READER_DB_PASSWORD'],
    database=os.environ['READER_DB_NAME'],
    charset='utf8mb4',
    autocommit=True
)

TABLES = [
    'reader_bookshelf',
    'reader_reading_history',
    'reader_reading_progress',
    'reader_content_audit',
    'reader_import_file',
    'reader_import_task',
    'reader_comic_page',
    'reader_comic_chapter',
    'reader_novel_chapter_content',
    'reader_novel_chapter',
    'reader_work',
]

conn = pymysql.connect(**DB)
cur = conn.cursor()

cur.execute("""
SELECT access_key, secret_key, bucket_name, endpoint, is_https
FROM sys_oss_config
WHERE config_key = 'minio' AND status = 'Y'
LIMIT 1
""")
access_key, secret_key, bucket_name, endpoint, is_https = cur.fetchone()

scheme = 'https' if is_https == 'Y' else 'http'
endpoint_url = endpoint if endpoint.startswith('http') else f'{scheme}://{endpoint}'

s3 = boto3.resource(
    's3',
    endpoint_url=endpoint_url,
    aws_access_key_id=access_key,
    aws_secret_access_key=secret_key,
    config=Config(signature_version='s3v4'),
    region_name='us-east-1'
)

bucket = s3.Bucket(bucket_name)
bucket.objects.delete()

cur.execute("DELETE FROM sys_oss WHERE service = 'minio'")

cur.execute("SET FOREIGN_KEY_CHECKS = 0")
for table in TABLES:
    cur.execute(f"TRUNCATE TABLE {table}")
cur.execute("SET FOREIGN_KEY_CHECKS = 1")

cur.close()
conn.close()
PY
```

## 7. 本次真实执行过程

本次实际采用的是：

- `Python + boto3 + pymysql`

执行顺序如下：

1. 查询 `sys_oss_config` 获取当前启用的 MinIO 配置
2. 连接 MinIO 并清空 `ruoyi` bucket
3. 删除 `sys_oss` 中全部 `service = 'minio'` 的记录
4. 关闭外键检查
5. 依次 `TRUNCATE` 所有阅读器业务表
6. 恢复外键检查
7. 再次统计确认清理结果

## 9. 如需只清阅读器数据但不清整个 Bucket

如果后续不想清空整个 `ruoyi` bucket，而只想清掉阅读器测试导入产生的对象，可以使用：

```bash
READER_DB_HOST="${READER_DB_HOST}" \
READER_DB_PORT="${READER_DB_PORT}" \
READER_DB_NAME=reader \
READER_DB_USER="${READER_DB_USER}" \
READER_DB_PASSWORD="${READER_DB_PASSWORD}" \
bash /Users/yabin/code/ruoyi/RuoYi-Vue-Plus/script/bin/reader-reset-remote-test-data.sh --reader-only
```

此模式只会：

- 删除阅读器业务关联的 OSS 记录和 MinIO 对象
- 清空阅读器业务表

不会粗暴清空整个 bucket。

## 10. 重置后建议操作

环境清空完成后，建议按以下顺序重新开始验证：

1. 重启后端服务
2. 重新上传测试小说或漫画文件
3. 创建新的导入任务
4. 检查导入进度、章节拆分、审核记录是否正确
5. 审核并上架
6. 在 H5/小程序端重新验证阅读链路

## 11. 注意事项

- `--all-bucket` 会清空整个 MinIO `ruoyi` bucket，务必确认里面没有其他非阅读器业务文件。
- 该操作属于高破坏性操作，执行前应确认当前环境确实是测试环境。
- 如果后续重新启用基于 `mc` 的脚本，务必先确认本机 `mc` 是否真的是 `MinIO Client`。
- 如果还是 `GNU Midnight Commander`，请继续使用本文档中的 Python 方式，或单独安装 `minio-mc` 后通过独立路径执行。
