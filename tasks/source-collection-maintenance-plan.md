# 书源批量采集与任务维护实施计划

## 目标

在现有书源站点、解析规则、限流策略和 Worker 协议之上，增加单本、全站和按分类采集方式。批量采集需要以“书名 + 作者”为作品唯一键，已存在作品只采集新增章节；新分类自动登记，任务页面展示批次、模式、时间、书籍和章节级进度，并支持查看单本书的章节与正文快照。

## 设计约束

- 继续沿用 `reader_source_task` 作为任务主表，保留现有单本任务兼容性。
- 新增 `reader_source_task_book` 作为任务书籍明细，承载一本书在某次采集批次中的状态和进度。
- 作品主表补充作者字段；通过规范化的书名和作者建立唯一去重键，避免重复生成作品。
- 新增独立分类表，作品保留分类名称兼容现有接口；采集发现的新分类自动登记。
- 快照先进入待审核链路，不允许 Worker 直接发布作品或章节。
- 保留 Java、Python、Go 的单本协议；批量协议先扩展为“发现书籍 -> 逐书抓取 -> 逐书上报”，旧 Worker 仍可继续处理单本任务。
- 所有访问继续经过站点授权、黑名单、robots、SSRF、限流、Retry-After 和熔断门禁。

## 验收口径

- 任务主表和书籍明细均可追踪采集批次、时间、模式、状态和进度。
- 同一作品的去重键为规范化书名 + 规范化作者，重复采集不会新建作品。
- 已有作品只抓取来源目录中高于本地最新章节或内容哈希变化的章节。
- 所有新增/修改的阅读器 Java、SQL 和前端代码均补充职责注释。
