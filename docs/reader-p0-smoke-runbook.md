# Reader P0 Smoke Runbook

> 更新时间：2026-08-12
> 目的：把第一次 P0 联调冒烟从“知道要做什么”变成“可以直接照着执行”

## 1. 适用范围

本 runbook 对应当前已确认的 P0 最小闭环：

`plus-ui` 上传导入文件 -> `ruoyi-reader` 生成草稿与待审核 -> 后台审核/发布 -> `reader-uniapp H5` 阅读 -> 保存书架/历史/进度 -> 微信小程序续读 -> 后台下架回滚前台可见性

## 2. 当前执行基线

| 维度 | 当前状态 |
| --- | --- |
| 后端 | `RuoYi-Vue-Plus` 分支 `analysis/reader-backend-fit` |
| 后台前端 | `plus-ui` 分支 `analysis/reader-frontend-fit` |
| C 端前端 | `reader-uniapp` 分支 `analysis/reader-miniapp-fit` |
| Java | `JDK 21` |
| P0 内容来源 | 文件导入 |
| C 端当前能力 | 详情页继续阅读、书架/历史跳转、阅读进度回填、H5/小程序平台标识写入 |
| 当前联调认证策略 | 首轮 P0 冒烟可临时复用现有 Sa-Token，不依赖正式微信登录落地 |

## 3. 进入冒烟前必须满足的条件

1. MySQL 可用。

5. `plus-ui` 可正常登录后台账号。
6. `reader-uniapp` 已配置正确的 API 基地址。
7. 如需验证登录态接口，需准备可用的 Sa-Token 与匹配的 `clientid`。

建议先执行一次前置检查脚本：

```bash

```

最近一次检查结果可参考：

`/Users/yabin/code/ruoyi/RuoYi-Vue-Plus/docs/reader-p0-smoke-precheck-report-2026-08-12.md`

### 3.2 账号与素材条件

1. 准备一个后台运营账号。
2. 准备一个可用于 H5 和微信小程序的同一读者身份。
3. 准备一个有效小说文件：
   `txt` 或 `epub`
4. 准备一个有效漫画文件：
   `zip` 或 `cbz`
5. 准备一个损坏文件用于失败路径观察。

## 3.3 当前已确认的联调阻塞与处理策略

截至 2026 年 8 月 12 日，已确认一个关键事实：

- `reader app` 的书架、历史、进度、个人中心接口当前都要求登录态。
- `reader-uniapp` 已预留移动端/微信登录接口封装，但后端读者侧正式登录控制器尚未落地。

因此第一次 P0 冒烟采用如下策略：

1. 不在本轮提前扩展正式微信登录实现。
2. 先复用现有后端 Sa-Token，验证书架、历史、进度、跨端续读等登录态业务闭环。
3. 等第一次 P0 冒烟完成后，再把正式登录/游客/身份合并作为下一阶段补强项推进。

## 3.4 `reader-uniapp` 本地联调环境变量

`reader-uniapp` 已支持以下本地联调环境变量：

| 变量 | 作用 | 示例 |
| --- | --- | --- |
| `VITE_READER_API_BASE_URL` | 读者端请求基地址 | `http://localhost:8080` |
| `VITE_READER_CLIENT_ID` | 请求头中的 `clientid` | `e5cd7e4891bf95d1d19206ce24a7b32e` |
| `VITE_READER_DEV_TOKEN` | 本地开发态注入的 Bearer Token | 留空或手动填写 |

建议做法：

1. 复制 `/Users/yabin/code/ruoyi/reader-uniapp/.env.development.example`。
2. 填写本地后端地址。
3. 如需跑登录态接口，填写与 Token 匹配的 `clientid`。
4. 在第一次联调冒烟期间，可临时填写 `VITE_READER_DEV_TOKEN` 复用现有登录态。

## 3.5 如何获取第一次冒烟要用的开发态 Token

当前建议优先复用 `plus-ui` 已登录后的 Sa-Token。

### 方案一：从 `plus-ui` 浏览器本地存储读取

1. 启动并登录 `plus-ui`。
2. 打开浏览器开发者工具。
3. 进入 `Application` 或 `应用` 面板。
4. 找到本地存储里的 `Admin-Token`。
5. 将这个值填入 `reader-uniapp` 的 `VITE_READER_DEV_TOKEN`。
6. 将 `VITE_READER_CLIENT_ID` 设置为：
   `e5cd7e4891bf95d1d19206ce24a7b32e`

### 方案二：直接从前端代码约定确认客户端 ID

当前 `plus-ui` 开发环境默认客户端 ID 为：

`e5cd7e4891bf95d1d19206ce24a7b32e`

因此第一次本地联调时，`reader-uniapp` 默认也应使用同一个 `clientid`，否则会出现：

`客户端ID与Token不匹配`

### 使用后的自检方式

完成环境变量配置后，可按下面顺序快速自检：

1. 启动后端。
2. 启动 `reader-uniapp H5`。
3. 进入“我的”页面，看是否仍然提示“未登录”。
4. 进入书架页，看是否从“请先登录后查看书架”变成可正常请求。
5. 打开一个已发布作品，尝试加入书架和保存阅读进度。

如果仍失败，优先检查：

1. `VITE_READER_DEV_TOKEN` 是否为空或复制不完整。
2. `VITE_READER_CLIENT_ID` 是否与 Token 的客户端一致。
3. 后端 `localhost:8080` 是否实际启动成功。
4. 当前 Token 是否已过期。

## 6. 本次冒烟必须覆盖的最小路径

### 6.1 小说链路

1. 登录 `plus-ui`。
2. 打开导入任务页。
3. 上传一个有效小说文件。
4. 确认成功创建导入任务。
5. 确认后端已生成：
   导入文件记录
   草稿作品
   最小章节
   待审核记录
6. 在审核页通过审核。
7. 在作品管理中发布该作品。
8. 在 H5 打开作品详情页。
9. 确认详情页能看到：
   作品信息
   目录
   继续阅读或开始阅读入口
10. 打开小说阅读页并至少保存两次不同进度。
11. 返回详情页，确认阅读进度已回填。
12. 打开书架页，确认能看到作品并可继续阅读。
13. 打开历史区，确认有最近阅读记录。

### 6.2 漫画链路

1. 在后台上传一个有效漫画文件。
2. 确认后端生成最小漫画章节和分页数据。
3. 审核并发布该漫画作品。
4. 在 H5 或微信小程序打开作品详情页。
5. 进入漫画阅读页。
6. 至少保存两次不同页码/进度。
7. 返回详情页，确认当前页码和进度信息已能回填。
8. 从书架或历史再次进入，确认能恢复到最近章节/页码。

### 6.3 跨端续读链路

1. 使用同一读者身份在 H5 打开已发布作品。
2. 在小说或漫画阅读页保存进度。
3. 切换到微信小程序打开同一作品。
4. 确认：
   详情页能看到最近进度
   点击继续阅读能打开最近章节
   漫画能够带出最近页码
5. 记录是否存在身份不一致、进度不一致、页码不一致问题。
6. 如果本轮使用开发态 Token 注入方案，也要记录：
   H5 与小程序是否实际使用同一 Token
   `clientid` 是否一致

### 6.4 下架回滚链路

1. 在前台先访问一次已发布作品详情与目录，触发缓存。
2. 后台执行下架操作。
3. 再次在 H5 或小程序访问该作品。
4. 确认：
   作品详情不可再按已发布内容访问
   目录不可再按已发布内容访问
   正文/图片阅读入口失效

| 小程序续读 | 作品 ID、章节 ID、页码、进度百分比 |

## 8. 本轮重点观察项

本次不是追求完美，而是优先验证最小链路是否真的跑通。重点观察：

1. 导入后是否必然生成草稿作品与待审核记录。
2. 审核通过后是否必然同步发布章节。
3. H5 阅读进度保存后，详情页是否立即能回填。
4. 书架页与历史页是否都能正确跳回阅读页。
5. H5 与微信小程序之间的进度、章节、页码是否一致。
6. 下架后缓存是否及时失效。
7. 损坏文件是否会形成脏数据或错误发布。
8. 使用开发态 Token 注入时，是否存在 `客户端ID与Token不匹配` 问题。

## 9. 失败时的归类规则

冒烟过程中发现问题后，建议立刻按下面方式归类：

### 9.1 P0 阻塞问题

满足任一条件即归为阻塞：

- 无法导入任务
- 无法生成草稿作品
- 无法审核或发布
- 前台无法读取已发布内容
- 无法保存阅读进度
- 书架/历史无法继续阅读
- H5 与小程序无法基于同一身份续读
- 下架后前台仍能继续读取已发布正文

### 9.2 P0 可接受遗留问题

可先记录，不阻断继续冒烟：

- 样式不完善
- 文案不准确
- 空状态不够友好
- 章节拆分不精细
- 漫画图片展示样式较粗糙

### 9.3 P1 后置问题

直接记录到后续，不在本轮展开：

- 合规授权源同步
- 推荐位、榜单、专题
- 消息中心、反馈中心
- 会员、付费、商业化能力

## 10. 本轮冒烟完成判定

满足以下条件，可认为第一次 P0 联调冒烟通过：

1. 至少 1 本小说完成：
   导入 -> 审核 -> 发布 -> H5 阅读 -> 书架/历史/进度写入
2. 至少 1 本漫画完成：
   导入 -> 审核 -> 发布 -> 阅读 -> 进度写入
3. 至少 1 次跨端续读完成：
   H5 保存进度 -> 微信小程序继续阅读
4. 至少 1 次下架回滚验证完成：
   下架后前台不可继续读取

## 11. 冒烟后的下一步

冒烟结束后按下面顺序继续：

1. 汇总问题清单。
2. 只优先修复 P0 阻塞问题。
3. 重新跑最小回归冒烟。
4. P0 稳定后再推进身份体系闭环。
5. 最后再启动 P1 合规授权源能力设计与开发。
